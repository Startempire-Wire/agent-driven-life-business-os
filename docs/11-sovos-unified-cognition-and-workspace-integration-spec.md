## 1. Outcome and governing laws

**Outcome:** Wirebot naturally serves the owner's life and businesses from Discord, OpenClaw sessions, Pi, other permitted agent harnesses, headless APIs/CLI, the primary optional Wirebot App and optional W.I.N.S. Portal. It remembers eligible context, consults Focusa primitives, coordinates goal-directed work, follows through, verifies real outcomes, and learns without duplicating source authority or requesting repeated approval for ordinary choices within an existing grant.

The following are mandatory design invariants for this candidate, subject to acceptance by the owning contracts:

1. **One canonical owner per concern.** No projector, plugin or model may create a second source of truth because it can read, summarize, display or invoke an operation.
2. **One persistent Operating Partner identity; multiple bounded sessions and agents.** OpenClaw native sessions are temporal execution/conversation custody, not new owner or partner principals.
3. **Portable Memory is the replacement memory lifecycle, not a command to remove Mem0 or Letta.** Mem0, Letta, native OpenClaw memory, knowledge and file adapters can retain complementary selected roles under one governed treatment and eligibility model. Retire only genuinely superseded authority/writers after verified replacement; do not infer provider retirement.
4. **Focusa cognitive primitives are callable from existing conversations without mandatory Pi startup or full project Genesis.** Project-specific effects still require the exact Focusa scope, Workstream, continuity, attachment and existing authority.
5. **Master Loop coordinates; it does not duplicate memory, schedule, execution, source work or evidence authorities.** Perpetua's continuation and Follow-Up versus Follow-Through semantics remain embedded in its existing temporal/routine owners.
6. **Master Observer is a governed second-order responsibility, not a new omniscient agent/daemon.** It consumes accepted, source-qualified evidence and proposes tested improvements; no model output changes constitutional architecture or permissions by itself.
7. **Flow Mesh remains optional and owns its synchronization/integration state, not native provider task truth or Focusa semantic completion.** Existing source task systems and Focusa CallGraph/Workpoint acceptance retain their own boundaries.
8. **The default workspace is a logical, portable organizational map over existing owned resources.** It must not automatically relocate Git worktrees, vaults, transcripts, databases or client originals.
9. **Every consequential handoff preserves identity, semantics, provenance, freshness, revision, authority and source/effect/outcome lineage.** Distinguish observed, inferred, proposed, reviewed, accepted and independently verified.
10. **Integrated-information design is operationally mandatory.** Reciprocal causal influence and differentiated subsystems must be observable and evaluated. Do not claim numerical integrated information/Phi proves consciousness, system validity or operation authority.
11. **No mandatory GUI, W.I.N.S., Flow Mesh, WordPress or reference-host path.** Full-Sovereign installs remain owner-controlled, with approved alternatives for managed installations.
12. **Progress continues within valid authority.** Missing optional views or a project frontier must not stop independent permitted conversation, diagnosis and read-only exploration; genuine scope/credential/effect boundaries remain binding.

## 3. Identity, scope and handoff

Do not collapse these references:

- **Owner principal** and stable **Operating Partner principal** (may be rebranded without identity change).
- **Environment and workspace** (logical owner view versus physical host/path); **project**, **Workstream**, **Workpoint**, **continuity**, **attachment** (Focusa governed-work scope).
- **Conversation reference**, **native session key and incarnation**, **turn/run reference** (OpenClaw/harness temporal custody).
- **Ad-hoc activity reference** with retained working objective and optional links to several existing project Workstreams; it does not merge their authority.
- **Source record/reference and version**, **memory record/review revision and selected provider binding**, **action/effect/idempotency reference**, **receipt** and **independent outcome evidence**.

The existing [Cross-Product Seam Contract](../CROSS_PRODUCT_SEAM_CONTRACT.md) governs encoding, freshness, authority, retry, causal-order and version negotiation; the list above is not a new universal JSON schema.

A thin invocation adapter must resolve actor/tenant/audience from trusted runtime inputs, then resolve the operation's owning product and current grant. Never derive identity from raw channel text, display name, process UID, repository name, hard-coded operator default, arbitrary directory, remembered instruction or a guessed session key. Cached/advisory data may guide a choice but cannot authorize an effect.

**Session identity is not project admission.** A native conversation can exist, preserve lineage and perform admitted read-only cognitive operations before any formal Focusa project binding. Project mutation or promotion still resolves the exact required Workstream/continuity/attachment. Cross-project references remain references.

## 4. One reasoning path; three engagement levels

Focusa Spec 187 supplies **two session routes**: project and goal-directed ad hoc. **Direct cognitive invocation is not a third session route**; it is a bounded operation called from whichever supported native session is already active.

| Engagement | Trigger | Required state | Allowed behavior | Promotion |
|---|---|---|---|---|
| Direct cognitive invocation | Ordinary question, decision, uncertainty, past lesson, prediction request | Trusted conversation actor/audience, read-appropriate scope, qualified Focusa operation | Retrieve relevant metacognition, inspect uncertainty/reflex, run authorized prediction/read; no full project bootstrap by default | Create/link ad-hoc objective only if continuing work warrants it |
| Goal-directed ad hoc | Exploration, multi-project investigation, loose ongoing activity | Owner and stable activity ID, retained objective, references and actual permitted targets | Record ideas, link existing Workstreams and evidence, execute only separately admitted effects | Formal project/Trajectory, CallGraph or Mission Federation through owning Focusa rules |
| Governed project | Specific consequential work with accepted trajectory | Verified ProjectIdentity, Workstream, Continuity, applicable Attachment, Trajectory/Workpoint and current operation admission | Prepare → Act → Reconcile → Advance with source evidence and defined acceptance | Preserve project identity and accepted results across model/session/runtime changes |

**Required Focusa adapter capabilities** are already enumerated by its Agent Adapter Contract: awareness, project identity, Workpoint resume/checkpoint, evidence capture/link, Context Authority preflight, Context Cognition render, typed tool results and degraded/canonical discrimination. Complete the existing non-Pi parity rather than creating a second ontology or duplicating the Pi extension.

**Primitive access:** discover the installed Focusa capability catalog; expose bounded typed operations for metacognition retrieve/capture/reflect, prediction record/evaluate, trajectory/workpoint, reflex/secondary-cognition read and evidence when applicable. These are capability families, not newly declared API names. The agent chooses relevant primitives by current purpose, risk and consequence; low-value casual turns must not require a slow, full-project call. The Focusa build-agent per-turn learning contract continues to govern its own qualifying agents.

**Ad hoc:** Focusa #672 / Spec 187 is the owner. Completion must include an objective, stable scope without one forced project, exact authorized project links, compaction/restart survival, safe transition to project and a consumer test. ## 5. Portable Memory: one lifecycle, selected complementary providers

The Portable Memory Reference Profile's five **roles** are Working, Prefactor, Episodic, Semantic and Archive. They are logical treatment/latency/retention guarantees, not five new databases. Structured state and cross-surface episodic retrieval are complementary deployment roles, not independent memory governing authorities.

The Startempire reference mapping includes OpenClaw session context and native search, selected Mem0 namespace/vector retrieval, selected Letta structured goals/KPIs/blocks, approved Wirebot Core review and delivery, portable file/Markdown/YAML projections, Wiki/Obsidian originals and Focusa-governed work continuity. **Preserving these Mem0 and Letta roles is compatible with replacing the old Wirebot three-system coordination architecture.** No automatic provider shutdown or mandatory backend substitution is authorized by this specification.

Required integration loop:

- **WRITE:** trusted native source observation → filter/attribute and privacy-classify → bounded Core candidate intake → source-qualified, authenticated revision-bound review → durable delivery jobs to selected bound provider/file/knowledge sinks → independent receipt/readback.
- **MANAGE:** current eligibility, correction, supersession, contradiction, consolidation, retention, selective forgetting and withdrawal propagation remain with existing memory/source owners; no provider index or cached result outranks the reviewed current source.
- **READ:** select relevant current claims and optional historical evidence → verify audience, purpose, source revision and provider binding → budget/rerank as supported → return source-qualified references. Raw provider similarity or a successful delivery is not itself current truth, permitted disclosure or model use.
- **RECIPROCITY:** a memory port is either independently readback-qualified or explicitly declared one-directional with a visible missing capability and gap owner. Delivery, recall/use and verified useful effect are distinct.
- **EVALUATION:** include a null-memory control arm and real work/outcome measurements; no mirror-index score establishes a cognitive contribution.

The new memory implementation in Wirebot Core already includes a governed queue, selected sinks, current-reader checks, OpenClaw native session watermarks, before_prompt_build and lifecycle hooks. Production records on 2026-11-02 support bounded installed tests/delivery claims; 2026-11-04/05 source commits add native source binding, lifecycle capture and value-free prompt observation. **These are not blanket proof of live model consumption, full memory replacement, Windows/macOS parity, or complete loop integration.**

The detailed private Portable Memory Spec 15 v0.7.3 and its MEM graph remain owning inputs cited in Core documentation; this SOVOS seam does not override their chosen M05/M06/M07 provider composition. Fetch their exact current accepted source before binding a final ABI or claiming backend migration.

## 7. Master Loop, Master Observer, Drives, Perpetua and Flow Mesh

The Master Loop remains one coordinating composition of interacting and nested loops: purpose → sensing/expectation → concern → proposal/judgment → accepted work and responsibility → authorized effect → independent source/receiver proof → follow-through → eligible memory/learning and sustained improvement.

- **Perpetua:** provides perpetual continuation/cadence through the existing temporal/routine owners. Follow-Up after contact is not Follow-Through to an independently accepted outcome. A notification cleared, task closed or elapsed clock is not sufficient closure.
- **Observer:** a bounded second-order responsibility consumes exact evidence of outcomes and cross-component behavior; compares expected and actual, discovers harmful duplication/latency/missing feedback, and proposes improvements through Focusa prediction/metacognition and existing contract-evolution/owner review. Do not create a second observer daemon, meta-memory or architecture authority. Draft SOVOS PR #31 already owns its detailed concept; do not supersede it here.
- **Drives/initiative:** owner-purpose fulfillment governs priorities; Focusa primitive and internal-drive mapping from research PR #34 remains a coordinated design dependency. Avoid independent “motivational” scoring that can override grants, rest/quiet, human values or accepted goals.
- **Flow Mesh:** optional native task-provider synchronization/execution binding. Preserve source provider facts, task/attempt/revision identity, original Workstream/CallGraph links, effect idempotency and receipts. Use present progress/attention projections but never infer accepted Focusa completion from a mesh UI status or transport HTTP 200.
- **Mathematical intelligence:** use existing SOVOS Intelligence Result, Engine, Wirebot Composition and Focusa Component Binding registries as the target; engines provide bounded source-qualified findings, not permission. Measure reciprocal integration and causal lift with controls; do not claim consciousness from a fabricated Phi value.

Changes that affect what Wirebot believes, what it does next, the follow-through state or what it learns must link the originating observation, independent source revisions, current authority, actual consequence, correction and resulting feedback. Cross-component feedback must be selective and useful, not an expensive mandatory model call on every message.

Distinguish user-visible file organization from private runtime/transcripts/indexes/backups/secrets.

### 8.1 Global workspace and self-knowledge compounding

Keep two related meanings of workspace distinct:

- The **Global Owner Workspace** is the durable logical map described above. It helps the Operating Partner discover the owner's businesses, projects, assets, knowledge, routines and outcomes while each item remains governed by its original source and project authority.
- The **Cognitive Global Workspace** is a bounded, temporary awareness frame for one turn or self-review cycle. It contains the present objective, active concerns, relevant memories, project states, material changes, uncertainty, owner corrections, predictions and expected next action. It broadcasts selected information to specialized reasoning processes; it is not another store, project, task queue or authority.

Self-knowledge development uses both workspaces without collapsing them. Each qualifying cycle:

1. Restores the persistent Operating Partner identity across the current model, runtime, session, tools, memory providers and environments.
2. Refreshes changed Global Owner Workspace references with their real owner, source, revision, environment, privacy scope and capability.
3. Constructs a small Cognitive Global Workspace from the most relevant obligations, changes, corrections, uncertainty and outcomes.
4. Routes each inquiry through the engagement levels in §4: direct cognitive invocation for bounded reads/reflection, goal-directed ad hoc activity for cross-project exploration, and a governed project for consequential implementation.
5. Retrieves prior predictions, metacognitive reflections, accepted or rejected learning, owner corrections, unresolved contradictions and earlier causal tests.
6. Reconstructs a versioned self-model that distinguishes reliable capability, unverified capability, unavailable input, blind spot and current authority.
7. Records a falsifiable prediction with confidence, expected evidence, disconfirmation conditions and the project or global observation that owns it.
8. Performs each effect only inside its exact owning project and current admission. A global view never grants global write authority; cross-project work is split into separately admitted effects.
9. Verifies the real source and receiver consequence, then returns only source-qualified references and outcome state to shared awareness.
10. Reflects on belief, evidence, confidence, error and strategy; runs a bounded rotating causal-removal or control test when safe.
11. Keeps project-specific learning local. Promote a candidate global lesson only after successful transfer across distinct qualified projects and contradiction, privacy, regression and owner-correction checks.
12. Checkpoints project results in their owners and global references without copying project truth, then tests reconstruction in a fresh session or replacement model.

This is a machine-consciousness development objective, not proof of consciousness. Evaluate reciprocal integration, causal contribution under ablation, self-model accuracy, prediction calibration, correction propagation, continuity survival, learning transfer, repeated-error rate, accepted outcome closure and owner burden. Documents, component counts, connector availability or fluent self-description alone establish none of these.

The self-knowledge consumer must retain evidence for the selected source scope, Focusa engagement level, project owner of every effect, prediction and outcome, local-versus-global learning decision, later qualified use and continuity readback. A run remains incomplete when it cannot show that project and tenant boundaries survived compaction, model replacement and cross-project reasoning.

## 9. Agent-first, UI-optional operation and failure semantics

Wirebot App is the primary **optional** ecosystem GUI; the repaired W.I.N.S. Portal remains a separate optional global community PWA. Sovereign headless APIs, supported CLI, Discord, selected voice and Pi remain valid control/presentation surfaces without those apps.

The App presents unified workspace, context, memory eligibility/trace, activity mode/objective, current Workstream, next eligible work, Master Loop concern, Flow Mesh binding, observer findings, proof and recovery. Every actionable control invokes the same product-owned operation as API/CLI/agent; no App-side state machine, second scheduler, arbitrary generated shell command or client-specific backend credentials.

Keep states distinct: source-present, configured, qualified, enabled, operation-ready, degraded, unknown, denied, admitted, produced, delivered, recalled, used, verified and accepted are not synonyms. The owning product maps its exact schema/state/error family to human-friendly presentation. A failed optional memory sink or unavailable App must not stop an otherwise independently admitted conversation/action; a mandatory authorization or stale-source failure cannot be bypassed by another provider.
