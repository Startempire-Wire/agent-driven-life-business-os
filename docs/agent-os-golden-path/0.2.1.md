## Purpose

0.2.1 makes the existing ADLBOS optimization loop mechanically safer and more empirical without replacing any canonical product owner or turning transcripts into automatic policy.

The update adopts the strongest reusable mechanics from transcript-driven agent-instruction optimization:

- source-bearing observations from real operation;
- explicit causal attribution;
- independent corroboration rather than raw session count;
- bounded/small candidate changes;
- semantic placement between always-loaded rules, load-on-trigger procedures and product-local contracts;
- explicit review/authority gates;
- post-rollout observation.

It adds the missing generalization safeguard:

> **Evidence used to derive a contract change is not independent validation of that change.**

Material semantic changes therefore require held-out behavioral regression cases plus protected-invariant checks before promotion.

## Non-regression law

This candidate does not authorize frequency-based erosion of established law.

Constitutional, safety/authority and architecture-boundary rules are protected classes. Low frequency, token cost, one ignored rule, one failed session, duplicate-looking wording or a newer tool is not sufficient evidence to weaken or remove them.

Semantic-preserving relocation/extraction is preferred when placement—not correctness—is the problem, and native consumer discovery/trigger behavior must be proven before relying on the new placement.

## Ownership law

No new learning authority is created.

```text
Canonical Owner Principal
  constitutional architecture / reserved powers

ADLBOS
  portable contract-evolution doctrine

Focusa
  governed project/work state, Evidence, receipts, continuity and product-owned learning

Wirebot
  Operating Partner context and owner-facing synthesis

W.I.N.S.
  accepted outcomes / corrections / economics

product repositories
  product-local behavior and operations

conversation / harness stores
  provenance sources, not automatic canonical memory
```

Product-local findings route to the owning product. The portable proposal schema references evidence/outcomes without copying private payloads into ADLBOS.

## Portable executable proof

The candidate adds:

```text

tests/fixtures/agent-contract-change.valid.json
tests/agent-contract-optimization-test.py
tests/run-contract-tests.sh
```

Run:

```sh
bash tests/run-contract-tests.sh
```

The regression policy checks protected-authority gating, independent-cause requirements for weakening/removal, held-out/derived separation, protected-invariant coverage and portable privacy constraints.

## Promotion path

```text
observed
→ corroborated
→ proposed
→ regression_tested
→ approved where required
→ rolled_out
→ verified

or

→ reverted
```

A commit is not `verified`. A transcript is not `approved`. A passing critique using the same derivation examples is not held-out regression proof.

## Honest limits

- This candidate does not implement a transcript collector, central optimizer service or product-runtime learner.
- Runtime/session evidence remains owned by its source systems and may require adapters before automated proposal generation is practical.
- The new contract/testing infrastructure is itself source-level proof; long-term post-rollout empirical benefit must accumulate through real operations.
- Existing 0.2.0 gaps and product acceptance work remain open unless separately proven closed.
