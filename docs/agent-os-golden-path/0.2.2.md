# Agent OS Golden Path 0.2.2

**Status:** candidate hardening update  
**Date:** 2026-09-27  
**Parent:** 0.2.1 evidence-gated contract evolution

## Purpose

0.2.2 tightens the dangerous transitions in agent-contract optimization without changing the ecosystem's product ownership, authority hierarchy, Golden Path stages, or ordinary ability to improve.

The refinement is additive: it preserves the 0.2.1 evidence-gated learning loop and closes mechanical paths that could otherwise permit an unfounded weakening, promotion, tradeoff, or extraction.

## Hardening

1. **Supersession is not harm.** Repeated `superseded` observations no longer count as independent harm evidence. Semantic weakening by supersession requires an exact `supersedes_ref` to a current owner-authorized contract.
2. **Portable promotion needs independent recurrence.** A `portable_operational` candidate may be explored and regression-tested early, but it cannot become `approved`, `rolled_out`, or `verified` from one causal incident.
3. **Tradeoffs are authority-bearing.** `tradeoff_approved` requires explicit owner or architecture-delegate authority plus an approval reference; a model/evaluator cannot approve its own regression.
4. **Extraction requires native-load proof.** A load-on-trigger extraction cannot reach `regression_tested` or later without at least one recorded native loader/trigger validation case.
5. **Schema and executable regression policy agree.** The portable proposal schema and regression test enforce the same boundaries rather than relying on prose alone.

## Non-regression statement

This candidate intentionally removes no current capability, authority invariant, product boundary, Golden Path step, evidence/outcome law, recovery rule, or operating lesson.

It does not make routine additive improvement harder than necessary. Higher proof is attached only to semantic weakening/removal, portable promotion, deliberate regression tradeoffs, and instruction-placement changes whose success depends on native loading.

## Validation target

```sh
bash tests/run-contract-tests.sh
```

Passing source-level contract tests prove structural policy consistency, not long-term behavioral improvement. Post-rollout operating evidence remains required before a candidate is called `verified`.
