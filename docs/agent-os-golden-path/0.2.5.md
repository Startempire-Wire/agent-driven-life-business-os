# Agent OS Golden Path 0.2.5

**Status:** candidate portable routine-library and runtime-closure planning completion  
**Date:** 2026-10-03  
**Parent:** 0.2.4 Base Feedback Loop Correction

## Purpose

Close the remaining planning/library gap between the SOVOS routine doctrine and a machine-checkable starter catalog, then turn the still-open runtime compiler gap into one exact vertical-slice acceptance plan.

This candidate does **not** claim the Wirebot → Focusa → OpenClaw routine compiler is implemented or proven in production.

## Portable library completion

The canonical `routine-templates/` catalog now covers the core routine families named by the doctrine, including newly materialized:

- finance operations;
- incident response;
- Evidence/closure;
- Quiet Kaizen / learning-improvement.

The routine-family schema gains the additive `evidence_closure` value so Evidence/closure is represented as a first-class portable routine family rather than being hidden inside generic custom behavior.

The canonical `routine-packs/` catalog now also represents the previously prose-only starter operating shapes:

- household/family;
- personal finance;
- wellness/care coordination;
- e-commerce/product commerce;
- local/field service.

Existing professional-services, software/SaaS, content/community and founder-portfolio packs now compose the relevant finance, incident, closure, workforce and Quiet Kaizen templates where appropriate.

## Portable/private boundary

The library generalizes recurring **patterns**, not the current operator's private Drive or customer payload.

Portable templates and packs carry no:

- private messages;
- customer records;
- credentials;
- active grants;
- exact schedules;
- canonical work state;
- source-domain outcome state.

Owner-specific evidence remains behind source refs in candidates/blueprints/instances and in the owning systems.

## Regression coverage

A new `tests/routine-library-coverage-test.py` regression requires:

- every canonical template to validate against `operator.routine_template.v1`;
- starter coverage of the doctrine's core routine families;
- every canonical pack to validate against `operator.routine_pack.v1`;
- all pack template refs to resolve to canonical template IDs;
- all starter life/business pack IDs to remain present.

The test is included in `tests/run-contract-tests.sh`.

This prevents the doctrine from silently growing beyond the machine-readable catalog.

## Runtime closure plan

`14-routine-compiler-runtime-closure-plan.md` defines the first exact executable slice:

~~~text
source observation
→ routine candidate
→ inquiry-triage template match
→ owner-specific blueprint
→ owner/governance acceptance
→ Focusa assignment/current grants
→ determinization
→ routine instance
→ exact trigger binding
→ shadow
→ bounded pilot
→ Evidence / receiver verification
→ source-domain accepted outcome
→ leverage snapshot
→ Quiet Kaizen
~~~

It also defines mandatory duplicate, stale-grant, wrong-tenant, provider-timeout, ambiguous-delivery, missed-run, overlap, takeover, revoke and incomplete-Evidence tests.

Generalization requires the same inquiry-triage template to work across two isolated operating shapes without leaking private payload or authority into the portable template.

## Preservation

This candidate does not:

- create another scheduler;
- create another work/authority/Evidence/outcome database;
- make W.I.N.S. mandatory;
- make a routine pack an identity classification;
- let a template activate itself;
- turn a schedule into authority;
- turn a learned owner preference into sovereignty;
- claim a runtime vertical slice has passed before evidence exists.

## Remaining open proof

`SAG-10` and `SAG-18` remain open until runtime evidence proves the compiler and steady scheduling path end to end.

Portable planning/library status and runtime implementation status must remain separate.
